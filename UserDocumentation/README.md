## Documentation Style Guide

When adding new user documentation:

1. **Write for non-technical users**
   - Avoid jargon and technical terms
   - Explain concepts in plain language
   - Use real-world examples

2. **Use clear structure**
   - Start with "Quick Start" or "Overview"
   - Break content into logical sections
   - Use numbered steps for procedures
   - Include screenshots where helpful

3. **Focus on tasks**
   - "How do I..." format
   - Step-by-step instructions
   - Clear success criteria

4. **Include troubleshooting**
   - Common problems and solutions
   - FAQ section
   - Where to get help

5. **Keep it updated**
   - Update docs when features change
   - Remove outdated information
   - Add new features as they're released

## Naming Convention

- Use descriptive names: `Feature_Name_Guide.md`
- Use underscores for spaces
- Use title case for multi-word names

Examples:
- ✅ `Agent_Configuration_Guide.md`
- ✅ `Document_Upload_Guide.md`
- ✅ `Business_Intelligence_FAQ.md`
- ❌ `guide.md`
- ❌ `technical-spec.md`
