# Data Analyst Test Scripts

Test scripts for the Data Analyst Agent feature using CrewAI flows.

## Prerequisites

1. **Backend running**: API server must be running on `http://localhost:5001` (or set `API_URL` env var)
2. **Celery worker running**: Celery worker must be running to process questions
3. **Database populated**: Insurance demo database should have data
4. **Authentication**: Test user credentials (default: `admin@example.com` / `admin123`)

## Environment Variables

```bash
export API_URL=http://localhost:5001  # API base URL
export TEST_USER_EMAIL=admin@example.com  # Test user email
export TEST_USER_PASSWORD=admin123  # Test user password
```

## Test Scripts

### 1. Single Question Test

Tests a single question through the full CrewAI flow:

```bash
python scripts/test_data_analyst_single_question.py
```

**With custom question:**
```bash
python scripts/test_data_analyst_single_question.py \
  --question "What is the total premium collected in the last quarter?"
```

**What it does:**
1. Authenticates with API
2. Submits a question
3. Waits for processing (polls status)
4. Handles clarification if needed (interactive)
5. Handles confirmation if needed (interactive)
6. Displays results (SQL, data, insights)

**Output:**
- Question ID
- Generated SQL
- Query results
- Insights (executive summary, key findings, anomalies, recommendations)

### 2. Conversation Test

Simulates a real analyst conversation with multiple messages:

```bash
python scripts/test_data_analyst_conversation.py
```

**Interactive mode** (prompts for clarifications/confirmations):
```bash
python scripts/test_data_analyst_conversation.py --interactive
```

**What it does:**
1. Authenticates with API
2. Submits multiple questions in sequence:
   - Initial question about premium data
   - Follow-up: "Can you break that down by state?"
   - Follow-up: "What about loss ratio by state?"
   - Ranking query: "Show me the top 5 states by premium"
   - Conversational: "What is our SOP for handling claims?"
3. Auto-clarifies and auto-confirms (unless `--interactive`)
4. Displays conversation summary

**Output:**
- Conversation ID (for multi-turn conversations)
- Message history with status, intent, SQL, results
- All messages appear in UI after test completes

## Test Flow

### Single Question Flow

```
User Question
    ↓
API Submit → Question Created
    ↓
Celery Task → CrewAI Flow Started
    ↓
Step 1: Intent Detection Agent
    ├─ DATA_QUERY → Continue
    ├─ CONVERSATIONAL → Continue
    └─ CLARIFICATION_NEEDED → Return to user
    ↓
Step 2: Clarification Agent (if needed)
    └─ User provides clarification → Continue
    ↓
Step 3: Confirmation Agent
    └─ User confirms → Continue
    ↓
Step 4: Router Agent
    ├─ DATA Query:
    │   ├─ VannaSQLGenerationTool → SQL
    │   ├─ SQLExecutorTool → Results
    │   ├─ InsightsGenerationTool → Insights
    │   └─ DatabaseMessageTool → Save
    └─ CONVERSATIONAL:
        ├─ ConversationalResponseTool → Response
        └─ DatabaseMessageTool → Save
    ↓
Results Available in Database & UI
```

### Conversation Flow

```
Message 1: "What is the total premium?"
    ↓ Creates Conversation
    ↓ Processes → Results
    ↓
Message 2: "Can you break that down by state?"
    ↓ Uses Conversation Context
    ↓ Processes → Results
    ↓
Message 3: "What about loss ratio?"
    ↓ Uses Conversation Context (last 10 messages)
    ↓ Processes → Results
    ↓
... (continues)
```

## Expected Behavior

### Successful Flow

1. **Question submitted** → Status: `pending` or `clarification_needed`
2. **Processing starts** → Status: `processing`
3. **Intent detected** → `detected_intent`, `intent_confidence` set
4. **SQL generated** → `generated_sql` populated
5. **Results returned** → `result_data`, `result_metadata` populated
6. **Status: completed** → All data available

### Clarification Flow

1. **Question submitted** → Status: `clarification_needed`
2. **Clarification prompt** → `clarification_prompt` populated
3. **User provides clarification** → `/clarify` endpoint called
4. **Question reprocessed** → With clarified question
5. **Results returned** → Status: `completed`

### Confirmation Flow

1. **Intent detected** → Status: `intent_confirmed`
2. **Confirmation message** → Generated by Confirmation Agent
3. **User confirms** → `/confirm` endpoint called
4. **Processing continues** → Status: `processing` → `completed`

## Troubleshooting

### Authentication Failed

- Check `TEST_USER_EMAIL` and `TEST_USER_PASSWORD`
- Verify user exists in database
- Check API is running and accessible

### Processing Timeout

- Check Celery worker is running
- Check Celery logs for errors
- Increase `max_wait_seconds` in test script

### No Results

- Check Vanna training data exists
- Check insurance database has data
- Check SQL generation succeeded (check `generated_sql` field)

### Clarification Loop

- System may need clarification multiple times
- Use `--interactive` mode to provide real clarifications
- Or set `auto_clarify=True` in test script
